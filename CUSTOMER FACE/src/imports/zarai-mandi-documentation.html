1. Product foundation

What Zarai Mandi actually is, stated plainly, before any screen gets designed.

Core identity
Zarai Mandi is not an AI assistant or an analytics dashboard.
It is a digital version of messaging a real Zarai Mandi representative.

What it replaces

Today, users get mandi prices by messaging WhatsApp groups — general community groups for open rate drops, and private one-to-one threads with a Zarai Mandi operator for a specific ask. The app digitizes both patterns without changing what the user is actually doing.

What it is not

Not a chatbot. Not "Ask Assistant." Voice input works like sending a WhatsApp voice note — but the reply comes back as a structured visual rate card, not a spoken answer or a conversational thread.

Design philosophy
Every screen should help the user make one agricultural decision in under 30 seconds.

2. General vs private subscriptions

The business model behind the data — this determines what a query is allowed to return.

General subscription

All-mandi rate data dropped at once, no personalization. Matches today's general WhatsApp community groups.

  • Browsing behavior
  • Fixed, shallow filter stack
  • Maps to Layer 1–2 usage

Private subscription

One customer, one Zarai Mandi operations contact, satisfying a specific need. Matches today's private WhatsApp threads.

  • Targeted, filter-stacked query
  • Detailed reply — arrival, largest buyer, trend, recommendation
  • Maps to Layer 3–4 usage
Worked example — private query

A stockist in Okara messages asking whether he should buy wheat today. The reply includes the date, the day's arrival volume, who the largest buyer was, and a trend-based read on whether price is likely to rise or fall — this full shape is what Layer 3's recommendation card is built to reproduce.

4. Personas & their stories

Same question format for everyone — mandi, price, product, min/max, arrival — differing only in depth and filter combination.

Farmer
Layer 1 · general
Messages the general wheat group most mornings to know what his own crop is worth locally before deciding to sell or hold. No mandi comparison, no rate-type filter — one number, fast, in his own mandi.
Retailer
Layer 1 · general
Checks the general group for wholesale rate on 2-3 commodities he restocks often. Narrow, fixed filter — same commodities, same rate-type, every time. Price-checking, not deciding whether to trade.
Commission agent
Layer 1 · general
Sits at the mandi floor itself. Uses the general group as a sanity check — confirming today's official numbers match floor activity, not discovering anything new.
Broker
Layer 2 · mixed
Trades across mandis — needs 3-5 mandis side by side on one commodity to spot a worthwhile spread. Occasionally goes private to confirm a specific rate-type (broker vs mandi rate) for a live deal.
Dealer
Layer 2 · mixed
Buys from mills, sells to retailers — needs two rate-types at once (mill rate + dealer rate) to know his margin. The clearest case of stacked filters at this layer.
Wholesaler
Layer 2 · mixed
Volume-driven — checks wholesale rate across a handful of mandis to decide where to source from this week.
Stockist
Layer 3 · private
The reference case for private queries: "should I buy wheat today?" Expects arrival volume, largest buyer, trend direction, and a hold/buy/sell read — paying for judgment, not just numbers.
Mill owner
Layer 3 · private
Needs arrival and trend over weeks, not one day — milling decisions depend on supply consistency, not a single price point.
Exporter
Layer 4 · private
Needs stockist-level analysis multiplied across regions or provinces at once — export decisions depend on comparing supply and pricing nationally, not locally.
Important nuance

The layer isn't fixed to the persona — it's fixed to the query. A stockist can ask a Layer-1-style question ("today's rate") or a Layer-3 one ("should I buy") depending on what he actually taps or types. The persona table shows typical depth, not a hard ceiling.

6. Filter logic

Four dimensions combine to form any query. The layer determines how much of each gets stacked — not which dimensions exist.

Commodity

wheat, cotton, onion...

Mandi

one, several, or all

Rate type

farm, broker, mandi, mill, dealer, wholesale, retail

Rate-type default

Rate-type filters show all types by default rather than requiring the user to build a selection from empty. A dealer narrows from "all rate types" to "mill + dealer only" in two taps — consistent with how Layer 1's rate list already shows everything with nothing pre-filtered out.

Why this matters for literacy

A user who has only ever opened Layer 1 already recognizes every element on Layer 4 — the row and the bar. Complexity increases in what's shown, never in how it's shown. This is the same principle that makes Facebook, Instagram, and Easypaisa usable without a manual: one visual vocabulary, reused everywhere, meaning carried by icon, color, and position rather than text density.

10. UI research & analysis

Why the design choices hold up against how the target users already behave online.

Baseline behavior of the target user

Observed pattern

The ~400 crore agri-family user base is already fluent in Facebook, Instagram, WhatsApp, and Easypaisa — apps built on big tappable tiles, icon recognition, and minimal reading, not dashboards or dense data tables.

Implication

The product should not teach a new interaction model. It should reuse the interaction model these apps already taught the user — action tiles that go somewhere, not information cards that display data.

Design decisions and their rationale

DecisionRationale
Big action tiles, not data cardsMatches Easypaisa-style shortcut tiles the user already navigates daily; tiles take the user somewhere rather than displaying information upfront.
Fully responsive by one component system1 column phone / 2 tablet / 4 desktop — never designed twice, so the same visual language holds across every device a user or professional might use.
No "AI Assistant" framingUsers are not asking an AI — they're messaging Zarai Mandi. Framing it as an assistant introduces an unfamiliar mental model; framing it as a rep they already message keeps the trust and behavior intact.
Weather/PAR forecasts kept off HomeThese are real, valuable, and already delivered informally via WhatsApp — but they are a secondary decision layer, not the primary one. Placing them on Home would break the "decision in under 30 seconds" rule.
Icon + row over table grid for rate dataFaster comparison scanning once more than 2-3 rows are shown, while photo tiles remain reserved for category entry points where recognition (not comparison) is the job.
Rate-type filter defaults to all-selectedAvoids requiring an illiterate or low-literacy user to build a selection from an empty state — narrowing down is a simpler mental action than building up.

Cross-app pattern references

Reference appPattern borrowed
EasypaisaLarge shortcut tiles for entry points; big buttons over dense menus
Google MapsHome asks one question ("where do you want to go") instead of showing everything at once
WhatsAppThe core interaction metaphor — messaging a known contact, general vs private groups
Linear / Notion / StripeOne responsive component system that reflows by breakpoint rather than being redesigned per device

Validated against existing behavior

Why WhatsApp already works, despite being a poor interface

Users succeed on WhatsApp today because it gets them to needed information quickly, not because the interface is good. The app's job is to preserve that speed while making comparison and deeper analysis easier than juggling multiple chat threads by hand.

11. Open decisions

Home for saved commodities, alerts, profile, subscription settingsOpen

The trimmed nav (Home / Graphs / News & Updates / Voice) has no obvious tab for these. Likely candidate: tucked behind a profile icon in the header rather than a fifth nav tab — needs explicit confirmation rather than deciding by omission.

Rate-type multi-select interactionDecided

All rate types shown by default; user narrows with a two-tap filter rather than building a selection from empty.
